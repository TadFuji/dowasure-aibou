# 開発記録の追記

藤川さんの常設依頼（2026-11-03）：「この制作手順、何をどう変えて何が問題だったかなど、細かく記録しておいてくださいね。最終レポートに入れたいと思っています。」「うまくいかなかったことも大きな財産ですので、それもしっかり記録しておいてください。」

記録は最終レポートと審査の材料になる。作業が終わった時ではなく、**変えたその場で** 追記する。

## 手順

1. `docs/開発記録.md` を読み直す（他のスレッドも書き込むため、最新を読んでから足す）。
2. 該当する日の見出し（`## 2026-11-03（火）` など）の下に、`### HH:MM 何をしたか` の見出しで足す。日本時間で書く。日が無ければ見出しを作る。
3. 中身は次の形にする。
   - 藤川さんの言葉があれば、**そのまま** 「」で引く。言い換えない。
   - 問題があった時は表にする：`| 問題 | 原因 | 対応 | 結果 |`。結果には **確かめた方法** を書く（テスト名、実機、計測の回数など）。
   - 見込みや推測は「📍」を付けて、確かめたことと分ける。
   - 数字は測ってから書く。計算したら「検算済み（言語名）」と書く。
4. 藤川さんの言葉は、末尾の「藤川さんの言葉（指示・困ったこと・気持ち）」の表にも1行足す：`| 日時 | 言葉 | 受けて変えたこと |`。
5. うまくいかなかった案は「うまくいかなかったこと・あきらめた案」の表にも1行足す。
6. 「これからやること」を、終わったものは消し、増えたものは足す。

## 書き方

- 結論を先に、一文を短く。専門用語には短い説明を添える（藤川さんはプログラマーではない）。
- やっていないことを書かない。予定は予定と書く。
- API キー、藤川さんの本物の記録、他人の実名は書かない。
- README の「作りながら直したこと」に載せるほど大きな変化なら、README にも1行足す。
