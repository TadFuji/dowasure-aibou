## 3. プロジェクト概要（3段落、合計467字）

1文目は決まった形「このプロジェクトは、〔誰〕の〔課題〕を〔どう変える〕〔形〕です。」に合わせました。字数は改行を除いて **全体467字**（1文目97字＋その下370字）。「その下に500字以内」がどちらの意味でも、500字に収まります（検算済み（Python））。

```
このプロジェクトは、スマホに不慣れな高齢の方の「さっき聞いた名前や約束が、ふっと出てこない」困りごとを、答えではなくヒントで自分で思い出せる時間に変える、話すだけで使えるiPhoneアプリです。
覚えておきたいことは、大きなボタンを押すか、Siriに「ど忘れ相棒で覚えて」と言って話すだけ。文字を打つ必要はありません。たとえば駅前で昔の同僚に会い、3日後に名前が出てこない時、「あれ、何だっけ？」と聞くと、相棒はすぐ答えを言いません。「3日前、駅前の喫茶店で会った方です」「前の職場の、丸い眼鏡の方です」「最初の音は『も』です」と、ヒントを少しずつ出します。自分で「森田さん！」と言えたら「ご自分で思い出せましたね」と喜びます。答えは頼んだ時だけ、日付つきで伝えます。
ヒントはClaude Haiku 5.5が作り、答えが漏れていないかをコードが確かめます。記録はiPhoneの中だけに保存します。ボタンは親指が届く下半分、文字は大きく、音量0でも文字と振動で使えます。65歳の制作者が実機で試し、感じたことを言葉にして直し続けました。
```

- 例の「森田さん」は、アプリに入っている架空の記録（`SampleData.swift`）の人物です。デモ動画の山場と同じ場面にしてあります。
- 医療の効果をうたう言葉は入れていません（「思い出す手伝い」の範囲）。

## 7. 開発中に一番詰まった場面

「音量0のとき、無音で待たされる」問題を選びました。高齢の方が実際にやりそうなことで、Claude が2回見立てを外し、藤川の一言で方針が変わった場面です。11/07 19:14〜19:53、4回のやり取りで直りました（[開発記録 19:15〜19:45](開発記録.md#1920-音量が0でも使えるようにした声を待たせない)）。

```
【何を作ろうとしていたか】
高齢の方が声で使うアプリです。「覚えておくことを話す」を押すと、アプリが「覚えておきたいことを、話してください。」と声で案内し、言い終えるとマイクが入り、iPhoneがブルっと振動して「話してください」と知らせます。アプリ自身の声を聞き取らないよう、声が終わってからマイクを入れる作りでした。

【Claude にどのように指示したか】
自分のiPhoneで試し、「『お話しください』と出て、iPhoneが一瞬ブルっとするのは、3秒後ぐらいですね。」と、感じたことをそのまま伝えました。

【何が起きたか、期待と何が違ったか】
Claudeはまず、案内の声の前後の無音を削って短くしました。私が「マナーモードにしていました」と言うと、Claudeは「マナーモードでも声は鳴る作りです」と説明しました。でも本当は、音量を0にしていました。そう伝えると、今度は「音が出ません。音を大きくしてください」と赤い字で出す直し方をしました。
私が期待していたのは、音量0のままでも待たされずに使えることです。利用者に設定を変えてもらう方向は、考えと違いました。さらに、話し終えた後の「もう一度きく」を押しても、音量0では何も起きませんでした。

【どのように対処したか】
「いえ、音量が0でも使えるUIにしてください。」と、方針をはっきり言葉にしました。Claudeは、声を出す1か所で音量を確かめ、0の時は声を出さずにすぐマイクを入れて振動するように直しました。「どうぞ、お話しください」は緑の大きな枠で示します。「もう一度きく」は、押すと振動と文字で知らせ、音量を上げた瞬間に読み上げます。そのたびにiPhoneに入れ直して、自分で確かめました。高齢の方は音量を下げたまま気づかないことがある、と学びました。
```

## 10. Claude を使った感想と改善してほしい点

```
【日本語や日本の仕事で使う立場から気づいた欠点と利点】
利点：65歳でコードを1行も書けない私が、ふだんの話し言葉で頼むだけで、iPhoneアプリを作り上げられました。「ロボットぽくて怖い」「ちょっと電子音っぽくて冷たさがありますね」のような感覚の言葉でも、Claudeは原因を測って直してくれました。高齢の方に伝わる日本語（「ホームにもどる」など）も一緒に考えてくれました。私が「全部徹底的に細かいところまで記録してくださいね」と頼むと、変えたことと私の言葉を日本語で記録し続けてくれたのも助かりました。
欠点：説明に専門用語が多く、「iPhone の iOS バージョンとは？」と聞き返すことがありました。「本文を貼ってください」と頼まれ、何をどこに貼るのか分からず2回聞き返したこともあります。また、Claudeが書いた点検の仕組みが日本語のファイル名（開発記録.md）を読み取れず、誤作動しました。日本語の入力では、シミュレーターの操作ツールで日本語が入らないこともありました。

【他の AI ツールと比べて劣る点と優れる点】
GitHubの見直しにはCodex、調べものにはMetaのMuseも使いました。優れる点：Claudeは、作って、自分で動かして確かめ、結果と失敗を記録するところまで一人でやってくれます。私の言葉を受けて直す、の繰り返しが速かったです。劣る点：声を作る機能が無く、声はGoogleのGeminiを使うしかありませんでした。また、Claudeの見落とし（日本語のファイル名の扱い、声の中継所の回数の上限）をCodexが見つけたこともあり、別のAIの目も必要だと感じました。
```
