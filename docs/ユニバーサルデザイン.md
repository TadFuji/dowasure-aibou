# シニアフリー・ユニバーサルデザイン

> **3行でいうと**
> 1. **答えを教えず、思い出す手伝いをします。** 忘れそうなことを話せば覚え、「何だっけ」の時はヒントを3段で出します。答えの言葉がそのまま入ったヒントはコードが捨て、言い換えの漏れは別の Claude（ヒントの係）が読んで点検しました。医療や診断はしません。
> 2. **高齢の方のために、細かいところまで作り込みました。** 65歳の藤川が実機で試し、その言葉で直す、を繰り返しました。直したことは [11行の表](../README.md#高齢者に使いやすくするために直したこと)に、藤川の言葉80件以上とうまくいかなかった案40件以上は [開発記録](開発記録.md) に残しています。
> 3. **何人もの Claude で、いろいろな方向から作り、点検しました。** 4人の係（Claude Code のサブエージェント。高齢の利用者役・ヒントの審査員・iOS の技術者・大会の審査員）に点検させて26件を直しました（[係の点検](係の点検.md)）。鍵の書き込みや医療めいた言葉は、フックが止めたり知らせたりします（[Claude活用](Claude活用.md)）。

**この文書で分かること：** 高齢の利用者に向けて決めた「見る・聞く・操作する」の決まりと、それぞれがコードのどこで実装されているか（`Palette`、`WarningText`、`wrapsForLargeText()`、`ThumbDock`、`elderScreen` など）、そしてまだ確かめていないことです。

最終更新：2026-11-07。

> 「高齢者は高周波は聞こえないことも考慮してください。ユビキタス、全体的に。」
> — 藤川（2026-11-03 14:30）

> 「非常にシンプルなUIと使い方で、高齢者がスマホなどに慣れていなくても直感的に使えること、それが非常に重要です。」
> — 藤川（2026-11-07 16:13）

前提にしたこと：目が見えにくい、高い音が聞こえにくい、話す前に考える時間がいる、親指が画面の上まで届かない、スマホの操作に慣れていない。この決まりは Claude Code への説明書（[`CLAUDE.md`](../CLAUDE.md)）にも書き、どのセッションの Claude も同じ決まりで作ります。

## 共通の部品

決まりを1か所で守るため、全画面が同じ部品を使います。ほとんどは [App/DowasureApp.swift](../App/DowasureApp.swift) にあります。

| 部品 | 何をするか | 使っている所 |
|---|---|---|
| `Palette` | 白い文字を載せる色。コントラスト比 4.5 以上の濃いオレンジ・濃い緑・濃い赤 | ボタンの地の色、注意の文字 |
| `WarningText` | 注意やエラーを、三角の印＋言葉＋赤で出す（色だけに頼らない） | 各画面のエラー、聞き取りの失敗 |
| `wrapsForLargeText()` | ボタンの文字を「…」で切らず、折り返して全部出す | すべての大きなボタン |
| `BigButton` | 高さ120pt（`Style.bigButtonHeight`）、文字は `title` の太字 | ホームの2つのボタン、「聞いてみる」 |
| `ThumbDock` | 画面の下の帯。押すものはすべてここ。ボタンの高さぶんだけの帯になり、入りきらない時（文字が最大の時）だけ帯の中が上下に動く | 全画面 |
| `elderScreen(タイトル) { ボタン }`（`ElderScreen`） | 上に大きな題名と読むもの、下の帯にその画面のボタンと「ホームにもどる」（高さ80pt）。読む所は最低でも高さ140pt（`Style.readingMinHeight`）を残す | ホーム以外の全画面 |
| `MicButton`・`MicStatus`（[Voice.swift](../App/Voice.swift)） | マイクのボタンは下（高さ100pt、緑／赤）、聞こえている言葉や「どうぞ、お話しください」は上 | 覚える画面、相談画面 |
| `RepeatButton`（[Voice.swift](../App/Voice.swift)） | 「もう一度きく」。音量0の時は振動と文字で返事をし、音量を上げたら自動で読み上げる | 覚える画面、相談画面 |
| `VolumeWarning`・`VolumeWatcher`（[Voice.swift](../App/Voice.swift)） | 音量がほぼ0（6%未満）の時に「音が出ていないので、文字とブルっという振動でお知らせします。」 | 全画面の上 |

## 見る

| 決まり | 具体的に | コード | 確かめ方 |
|---|---|---|---|
| 文字とボタンは大きく | 主なボタン120pt、マイク100pt、「ホームにもどる」80pt、下の帯のボタン72pt、その他64pt。文字は `title2` 以上 | `Style`、`BigButton`、`MicButton` | シミュレーターで目視 |
| 最大の文字サイズでも切れない | ボタンの文字は折り返す。読む所はスクロールできる。下の帯は入りきらない時だけ動く | `wrapsForLargeText()`、`ThumbDock` | iPhone の文字サイズを最大にして目視（11/03） |
| 白い文字の背景はコントラスト比4.5以上 | 濃いオレンジ 5.31、濃い緑 5.45、濃い赤 5.91（iPhone 標準のオレンジ・緑は約2.2で不可） | `Palette` | WCAG 2.x の式で計算（Python で検算） |
| 色だけに頼らない | 注意は三角の印と言葉。保存の結果は ✓ か三角の印。思い出せた回は星の印＋文（文字は普通の色、星だけ緑） | `WarningText`、`SettingsView`、`HomeView` | 画面テスト |
| 戻り方が分かる | 左上の小さな矢印をやめ、どの画面も下に大きな「ホームにもどる」 | `ElderScreen`（ナビゲーションバーは隠す） | 画面テスト |
| 読むものは上、押すものは下 | 上半分は質問・ヒント・答え・聞こえた言葉だけ。ボタンは下の帯へ | `elderScreen`、`ThumbDock` | 画面の写真で、押すものの上端を目測（11/07 18:28）：ホーム51%、覚えておくこと78%、あれ何だっけ63%、設定54% |
| 設定も下から | 項目が多いので、一覧の始まりを画面の高さの3割ぶん下げ、上には「指で上へずらすと、続きが出てきます」 | `SettingsView`（`contentMargins`） | 同上 |
| キーボードで隠さない | 設定ではキーボードが出ている間だけ下の帯を隠す。保存後はキーボードを閉じ、結果の行を画面の真ん中へ送る | `ElderScreen(hidesDockWithKeyboard:)`、`SettingsView` | 画面テスト `testSavingKeyShowsConfirmation`（11/07 18:18） |
| 縦向きだけ | 画面の向きを縦に固定 | [project.yml](../project.yml) | — |

コントラスト比は WCAG 2.x（Web のアクセシビリティの国際的な目安）の式で求めました。AA の基準は、普通の大きさの文字で4.5以上です。

## 聞く

| 決まり | 具体的に | コード |
|---|---|---|
| 音は低く | 待ち時間の「ポンポンポン」は 392Hz（ソ）と、その倍音 784Hz だけで1kHz未満。こだまの高い成分は1.5kHzで切る。言い当てた時のチャイムはソ（392Hz）→ド（523Hz）で、倍音を入れない | `Speaker.tonePattern`、`chimePattern`、`prepareEngine`（[Voice.swift](../App/Voice.swift)） |
| 冷たくない音 | 立ち上がりがやわらかく長く消えていく木琴のような音に、こだまと広い部屋の響き。音声素材は使わず計算で作る | 同上 |
| 声は低め・ゆっくり・はっきり | Gemini には「少し低めでやわらかく、ゆっくり、子音をはっきり」と指示。iPhone の声は高さ0.9倍、「ゆっくり」で速さ0.9倍 | `Speaker.style(for:)`、`Speaker.sayAndWait` |
| 怖くない声 | 機械っぽい変わった声（Eddy など）は候補から外す。既定は Gemini の自然な声 | `Speaker.isRegularJapanese`、`usesCloudVoice` |
| チャイムと声を重ねない | チャイムの後0.9秒待ってから話す | `Speaker.celebrateThenSay` |
| 音だけに頼らない | 話した言葉、ヒント、答え、エラーは必ず文字でも表示する | 各画面の `aiQuestion`・`answerText` |
| 音が出なくても使える | 音量がほぼ0の時は声を飛ばしてすぐマイクへ進み、振動で知らせる。話す番は「どうぞ、お話しください」を大きな緑の字と枠で出す | `Speaker.sayAndWait`、`VolumeWatcher`、`MicStatus` |

## 話す・操作する

| 決まり | 具体的に | コード | 理由 |
|---|---|---|---|
| 考える時間を待つ | 話し始めるまで20秒待つ。話し始めてからは4秒の間で区切る | `VoiceTiming` | 「何を話すか考えているうちに、元に戻ってしまいます」（藤川、11/03） |
| ボタンの名前が途中で変わらない | 画面を開いた時から「話し終わった」を出す（マイクは案内の声の後に入る） | `MicButton(waitingToListen:)` | 「『声で話す』ボタンがしばらく表示され、そのあとに『話し終わった』ボタンに変わりますね。ここは少し混乱します。」（藤川、11/07） |
| 話し始める時が目で分かる | 案内の間は「ブルっとしたら、お話しください」 | `MicStatus` | 声が終わるまで待たされている感じがあった（藤川、11/07） |
| 始まりと終わりを振動でも | マイクが聞き始めた時と止まった時に短い振動。言い当てた時は「成功」の振動 | `VoiceInput.start`・`stop`、`Speaker.celebrateThenSay` | 耳が聞こえにくい方にも分かるように |
| 聞き間違いに気づける | 話した言葉を「『…』ですね。覚えました。」とそのまま読み返す。相談では質問を「『…』について」と上に出す | `MemoLog.confirmation`、`AskView` | 音声認識の間違いを、その場で直せるように |
| 外れた時に責めない | 「『守田さん』と聞こえました。記録の言葉とは少し違うようです。」 | `HintSession.notMatchedPrefix` | 正しい名前を言ったのに漢字が違うだけのことがある |
| 間違いは取り消せる | 「いまのを取り消す」で直前の1件を消す | `TalkView.undoLast` | 操作の失敗を怖がらずに使えるように |
| 聞き逃しても聞き直せる | 「もう一度きく」 | `RepeatButton` | 画面を見ていない時もある |
| 答えはすぐ言わない | まずヒント3つ。名前を言えば「そうです！」、「答えを教えて」で答え | `HintSession` | 自分で思い出せた方がうれしい（アプリの目的） |
| 選ぶものを少なく | ヒントの画面は大きなボタン3つ（思い出したことを言う／もう少しヒント／答えを教えて）。文字の欄は「文字で答える」を押した時だけ | `AskView.hintControls` | 5つ並んでいて迷いやすかった（11/07） |
| 採点されている感じを出さない | 思い出せた回は励ましだけ。0回の時は何も出さない | `RecallLog.homeMessage` | — |
| 準備は家族向けに分ける | 鍵の入力は「はじめの準備（ご家族向け）」、書き出しと消去は「記録の保管（ご家族向け）」に畳む。消去はさらに奥 | `SettingsView` | ふだん使う人が迷わない・間違えて消さない |
| 準備がまだと分かる | 鍵が無い時、ホームに「はじめの準備がまだです」と、下のボタンを「準備をする（設定）」に | `HomeView.setupNotice` | 覚えるたびに失敗したように見えていた（11/07） |
| アプリを探さなくてよい | Siri の「ど忘れ相棒で覚えて」「ど忘れ相棒で何だっけ」、毎晩のお知らせから画面が開く | [SiriShortcuts.swift](../App/SiriShortcuts.swift)、[EveningReminder.swift](../App/EveningReminder.swift) | 「パッと話して」 |

## まだ確かめていないこと

- VoiceOver での操作の通し確認。
- 実際の高齢の方（藤川以外）による試用。
- 藤川の iPhone を右手で持って、下の帯に親指が届くか、押し間違えないか。
- 画面の小さい iPhone（SE など、高さ667pt）では、ホームの下の帯（約350pt）が画面の半分（約333pt）を少しはみ出す見込み（計算だけで、実機ではまだ見ていません。開発記録 11/07 18:15）。
- **ダークモード（画面全体が暗い表示）は、画面ではまだ見ていません。** 11/07 夜、計算で足りなかった所を直しました。`Palette` の緑と赤は、黒い背景との比が赤 3.55・緑 3.85 で、文字の色としては 4.5 に届きませんでした。そこで、文字と印に使う色（`Palette.greenText`・`Palette.redText`）を分け、暗い表示の時だけ明るい緑と赤にしました（暗い表の行 #1C1C1E との比 緑 7.9・赤 6.7。WCAG の式で計算）。明るい表示の色は変えていません。白い文字を載せたボタンの地の色は、表示の明るさにかかわらず 4.5 以上です。
- 枠だけのボタン「答えを教えて」（オレンジの文字に薄いオレンジの地）は、地の濃さを 15〜20% と見て計算すると、明るい表示で 4.0〜4.3、暗い表示で 3.5〜3.6 です。文字は 22pt の太字なので、WCAG の「大きな文字」の基準 3 以上は満たしますが、4.5 には届きません。地の濃さは iOS が決めるもので、実際の値はまだ測っていません。
- 毎晩のお知らせが実機で届くか（シミュレーターでは通知の許可がもらえないため）。
