# ど忘れ相棒 開発記録

制作の手順、変えたこと、起きた問題とその原因・対応を、時系列で残します。最終レポートの材料です。日時は日本時間。

- 制作者：藤川（65歳、プログラマーではない）。企画・実機での試用・判断を担当。
- 開発：Claude Code（Claude）。設計・実装・テスト・修正を担当。藤川さんはコードを書いていません。
- 表の見方：問題 → 原因 → 対応 → 結果（確かめた方法）。

## Claude Code の使い方（役割分担）

| 使ったもの | 何に使ったか |
|---|---|
| 本体のエージェント（Claude Opus） | 設計、実装、テスト、統合、藤川さんとのやり取り |
| サブエージェント（Sonnet） | 採点テスト一式（架空の記録25日・質問30問・採点ツール）の作成。本体が結果を再実行して確認 |
| サブエージェント（独立の点検役） | 公開前に、全履歴に API キーや個人情報が入っていないかを、本体とは別の目で点検 |
| サブエージェント（Web 読み取り） | Google の音声合成の仕様調査 |
| MCP（iOS シミュレーター操作） | シミュレーターの画面を撮影・タップして、見た目と動きを確認 |
| ブラウザ操作 | Google の料金表を公式ページで確認 |
| フック（git の pre-commit） | `sk-ant-` で始まる API キーや `private-data/`・`secrets/` のファイルがコミットされるのを自動で止める |
| 自動テスト | 中核部分の単体テスト（Swift Testing）と、画面の通しテスト（XCUITest）。本物の AI を使う画面テストも含む |

## 2026-11-02（月）

### 16:04 準備と計画
- 仕様書（2026-10-14）と大会ルール（参加者ガイド）を読み、最初に作る部分の計画を藤川さんに送った。
- 方針：声は後回しにして、まず文字入力で「記録 → 要約・抜き出し → 質問 → 根拠の日付つきの答え」を一本通す。
- Anthropic の資料（Building Effective Agents など）に合わせ、自律エージェントではなく、手順が決まったワークフロー型にした。Managed Agents は「記録を端末の外に保存しない」という約束と合わないので使わない。
- 公開リポジトリが必須なので、初日から API キーと個人の記録が入らない仕組み（`.gitignore`、pre-commit フック）を作った。

### 16:19 最初の動く版
- 中核部分（DowasureCore）：Claude API を直接呼ぶ部品、記録の候補日を端末内で絞る検索、答えの検証。
- **工夫：根拠の日付は AI に書かせない。** AI が「根拠にした」と返した日付のうち、実際に AI へ渡した記録の日付だけを残し、「10月8日の記録より：」の文言はアプリ側で組み立てる。残らなければ「記録には見当たりません」と答える。作り話を仕組みで防ぐため。
- AI の答えは構造化出力（JSON スキーマで形を決める機能）で受け取る。
- 確認：中核の自動テスト15件、画面の通しテスト1件が成功（AI 部分は模擬の応答）。

| 問題 | 原因 | 対応 | 結果 |
|---|---|---|---|
| シミュレーター操作ツールのスクリーンショットが古い画面を返した | ツール側の不具合 | `xcrun simctl io` で直接撮影する | 正しい画面を確認できた |
| シミュレーター操作ツールで日本語が入力できない | 貼り付け方式の入力が日本語で失敗 | 日本語入力は XCUITest（画面テストの仕組み）で入力する | 日本語の質問を入れたテストが成功 |
| 途中で iOS 27 のシミュレーターが使えなくなった | シミュレーター環境の不具合（runtime profile not found） | iOS 26.5 の専用シミュレーター「Dowasure-iPhone」を作った | 以降のテストは専用機で実行 |

### 16:30 声の入力と読み上げ・採点テスト
- 声での入力（iPhone 内蔵の音声認識、できるだけ端末内で処理）と、答えの読み上げを追加。
- 採点テスト一式をサブエージェント（Sonnet）に作らせた。罠として、眼鏡の人が2人、同じ場所に2回、変更された約束、似た名前（田村さん／村田さん）、記録に答えが無い質問8問を入れた。
- AI を使わない検索だけの採点：正解の日を候補に拾えた割合 21/22。

| 問題 | 原因 | 対応 | 結果 |
|---|---|---|---|
| マイクの許可を押した直後にアプリが落ちた | 許可の返事が裏の処理の流れで届くのに、画面用の処理として扱っていた（Swift 6 の安全確認で停止）。クラッシュ記録の `_dispatch_assert_queue_fail` で特定 | 返事を受け取る部分を、画面用の処理から切り離した | 許可 → マイク開始まで落ちないことをシミュレーターで確認 |
| シミュレーターで声が聞き取れない | シミュレーターでは端末内音声認識の初期化に失敗する（Code=300） | 失敗した時は「うまく聞き取れませんでした」と画面に出す。声の確認は実機で行う | 案内表示を確認。実機では後に成功 |
| 音声認識の許可画面の説明が「iPhone の中で文字にします」と言い切っていた | iPhone によっては端末内で処理できず Apple に送られる場合がある | 「できるだけ iPhone の中で処理します」に改めた | 説明と実際の動きが一致 |

## 2026-11-03（火）

### 07:33〜07:40 API キーの保存（藤川さん）
| 問題 | 原因 | 対応 | 結果 |
|---|---|---|---|
| キーを保存したはずが、ファイルの中身が命令文になっていた | 「キーをコピー → 命令文をコピーして貼り付け」の順だったため、命令文をコピーした時点でキーが上書きされた（手順の作りの誤り） | 命令文を先に実行し、止まったところでキーを貼り付ける方式（`read -rs`）に変えた | 正しく保存できたことを、中身を表示せずに形式だけで確認 |
| Google ではなく Anthropic の画面で「ID 連携を使えばキー不要」という案内が出た | サーバーやクラウドから呼ぶ場合の仕組みの案内 | 端末から直接呼ぶアプリなので「API キーで続ける」を選ぶよう案内 | キーを作成できた |

### 07:43 本物の AI で確認
- 本物の AI（Claude Haiku 5.5）で採点：答えのある22問中21問正解、記録に無い8問はすべて「見当たりません」。
- 外れた1問「先月、柿って何個とれたっけ」は、検索で正解の日が候補7件に入っていなかった。「柿」のような漢字1文字の言葉が、文字2つ組の一致では拾えなかったため。漢字1文字の一致も手がかりに加えた。
- 再採点：22/22、記録に無い質問 8/8。
- 注意：採点データは制作側が作った30問で、このデータで効果を確かめながら直したため、実際より良い点の可能性がある。藤川さんの実際の記録でも確かめ直す。
- 画面の通しテスト（本物の AI）：記録 → 質問 →「◯月◯日の記録より：青山さん…」を確認。

| iPhone で API キーの「保存する」を押しても画面が変わらない | 「保存しました」の表示が画面のいちばん下に出ていて、見えていなかった | 表示をボタンのすぐ下に移した | 画面テストで確認 |

- 07:53 藤川さんが実機で「話す → 記録 → 思い出す」を確認。

### 08:00 夜の聞き取り
- AI が1問ずつ声で聞く「夜の聞き取り」を追加。最初の質問と質問数の上限（7問）はアプリ側で決め、次に何を聞くかだけを AI が選ぶ。
- 台本の答えで本物の AI と何度か会話させ、話し方を調整した。
  - 1回目：名前の確認と次の質問を一度に聞いていた → 「確かめる回はそれだけを聞く」と指示。
  - 2回目：「楽しい時間でしたね」と気持ちを決めつけた／質問で終わらない回があった → 「気持ちを決めつけない」「続ける時は必ず質問で終える」と指示。
  - 3回目：1問ずつ聞き、「特にない」「疲れた」で早めに終えるようになった。

### 08:05〜08:23 藤川さんの実機の感想から直したこと
| 問題（藤川さんの声） | 原因 | 対応 | 結果 |
|---|---|---|---|
| 「声で話す」を押して何を話すか考えているうちに元に戻ってしまう | 3秒黙ると終わる作りで、話し始める前の考える時間も同じ扱いだった | 話し始めるまでは20秒待ち、話し始めてからは4秒の間で区切る。黙ったまま止まった時は理由を表示 | 待ち時間の単体テストを追加 |
| 左上の小さな矢印だけでは戻り方が分かりにくい。高齢者向けなのでもっと大きく分かりやすく | 標準の画面部品のままだった | どの画面にも下に大きな「ホームにもどる」ボタン。文字とボタンを全体に大きく。設定は「お知らせ」「声」だけを上に出し、準備用の項目は畳んだ | 画面テスト5本が成功、見た目をシミュレーターで確認 |
| 声がロボットっぽくて怖い | iPhone に最初から入っている簡易版の声（Kyoko 標準）を使っていた | iPhone に入っている中でいちばん自然な声を自動で選ぶようにした | → 次の問題につながった |

- 毎晩のお知らせ（既定20時、時刻は設定で変更）を追加。通知を押すと聞き取りが始まる。
  - 問題：シミュレーターでは通知の許可が仕組み上もらえない（UNErrorDomain 1）。許可されなかった時の案内が「止めました」で上書きされる不具合も見つけて直した。実際に届くかは実機で確認する。

### 08:35〜08:40 声の変遷
| 問題（藤川さんの声） | 原因 | 対応 | 結果 |
|---|---|---|---|
| 声が逆にめちゃくちゃ怖くなった。低い男性の声になった | iPhone の日本語の声には、わざと機械っぽくした変わった声（Eddy、Grandpa など）が入っている。「いちばん自然な声」を選ぶ処理が、品質が同じ声を名前の順に並べたため、Eddy を先に選んだ（Mac で声の一覧を出して確認） | 変わった声は候補から外し、女性の声を優先 | Kyoko に戻った |
| それでも非常にロボットっぽい。「昭和、1980年代に戻ったよう。2026年風にしてほしい」 | iPhone 内蔵の声の限界。高品質版は利用者が設定アプリから手でダウンロードする必要があり、アプリからダウンロードさせる仕組みは Apple が用意していない | 選択肢を提示し、藤川さんが「Google の AI 音声（Chirp 3: HD）」を選択 | 次項 |

### 09:58〜 自然な声（Google の音声合成）
- 料金を Google の公式料金表で確認：Chirp 3: HD は毎月100万文字まで無料、超えた分は100万文字あたり30ドル。支払い方法の登録が必須。読み上げは1人1日およそ600文字の見込みで、無料分で約50人分（検算済み・Python）。
- 作り：Google のキーがあれば Google の声で読み上げ、キーが無い・通信に失敗した時は iPhone 内蔵の声に自動で切り替える。Google に送るのは読み上げる文だけ。
- 状態：Google Cloud の登録を藤川さんに案内中。
