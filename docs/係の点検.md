# 4人の係に点検させた記録

> **3行でいうと**
> 1. **答えを教えず、思い出す手伝いをします。** 忘れそうなことを話せば覚え、「何だっけ」の時はヒントを3段で出します。答えの言葉がそのまま入ったヒントはコードが捨て、言い換えの漏れは別の Claude（ヒントの係）が読んで点検しました。医療や診断はしません。
> 2. **高齢の方のために、細かいところまで作り込みました。** 65歳の藤川が実機で試し、その言葉で直す、を繰り返しました。直したことは [11行の表](../README.md#高齢者に使いやすくするために直したこと)に、藤川の言葉80件以上とうまくいかなかった案40件以上は [開発記録](開発記録.md) に残しています。
> 3. **何人もの Claude で、いろいろな方向から作り、点検しました。** 4人の係（Claude Code のサブエージェント。高齢の利用者役・ヒントの審査員・iOS の技術者・大会の審査員）に点検させて26件を直しました（[係の点検](係の点検.md)）。鍵の書き込みや医療めいた言葉は、フックが止めたり知らせたりします（[Claude活用](Claude活用.md)）。

**この文書で分かること：** `.claude/agents/` に置いた4人の係（サブエージェント）を、どんな人として作り、いつ実際に呼んで、何を見つけ、何を直したか。作った Claude 本人とは別の目で見るための係です。

- 4人とも、藤川の Mac の Claude Code から、**係の名前（`subagent_type`）を指定して** 呼びました。4人は同時に動かしました。

### ここで止めた理由

3回目と4回目で、指摘が行ったり来たりしました。

- 短い答え（野球・白・3勝）は、**最初の音を言うと答えがほぼ分かる**。
- かといって **最初の音をやめると、3つ目が答えの手がかりにならない**（3回目の入浴料・歩数）。

これは指示文の言い回しでは両立しにくい、アプリの考え方の問題です。3つ目は「答えの直前の、一番近いヒント」なので、短い答えで最初の音を言うのをどこまで許すかは、藤川が決めることにしました。今は 5c5110c の決まり（最初の音を言う）のままです。**11/07 23:13、藤川が「今のまま最初の音を言う」を選びました。** 3つ目は答えの手前の最後の一押しなので、ほぼ分かってもよい、という判断です。これは点検の前（aff05a3）と同じ考え方で、そのうえで点検で見つかった漏れ（「◯月の明日」「山や空の本」）を防ぐ決まりが足されています。

また、採点は毎回1回しか流しておらず、AI の答えは回ごとに少しずつ変わります。回ごとの違いの一部は、この揺れかもしれません（同じ版を2回流して比べてはいません）。
