# 採点

> **3行でいうと**
> 1. **答えを教えず、思い出す手伝いをします。** 忘れそうなことを話せば覚え、「何だっけ」の時はヒントを3段で出します。答えの言葉がそのまま入ったヒントはコードが捨て、言い換えの漏れは別の Claude（ヒントの係）が読んで点検しました。医療や診断はしません。
> 2. **高齢の方のために、細かいところまで作り込みました。** 65歳の藤川が実機で試し、その言葉で直す、を繰り返しました。直したことは [11行の表](../README.md#高齢者に使いやすくするために直したこと)に、藤川の言葉80件以上とうまくいかなかった案40件以上は [開発記録](開発記録.md) に残しています。
> 3. **何人もの Claude で、いろいろな方向から作り、点検しました。** 4人の係（Claude Code のサブエージェント。高齢の利用者役・ヒントの審査員・iOS の技術者・大会の審査員）に点検させて26件を直しました（[係の点検](係の点検.md)）。鍵の書き込みや医療めいた言葉は、フックが止めたり知らせたりします（[Claude活用](Claude活用.md)）。

**この文書で分かること：** 「あれ、何だっけ？」が正しく答え、記録に無いことを作らず、ヒントで答えを漏らさないかを、決まった問題でどう測っているか。最新の結果（2026-11-07）と、この採点では分からないこと（限界）です。

最終更新：2026-11-07。結果の数字はすべて [開発記録.md](開発記録.md) から写しています。

## 結論

- 最新（2026-11-07、Claude Haiku 5.5、本物の API）：答えのある22問は **22問正解**、記録に答えが無い8問は **8問とも「見当たりません」**、ヒントの自動点検での漏れは **0問**。1問あたりの待ち時間は平均4.4秒、最長8.6秒（Mac から計測、今のコード 5c5110c）。ただし、ヒントの係が1つずつ読むと、短い答え（野球・白・3勝）の最初の音を出す3問が「漏れに近い」と判定されました（下の表の「係 3/22」）。11/07 23:13、藤川が「今のまま最初の音を言う」と決めました（下の「11/07 のヒントの直し」）。
- ただし、自動の点検で0問でも、人の目で読むと漏れが見つかったことがあります（下の「11/07 のヒントの直し」）。採点データも小さく、制作側が作ったものです。**この数字は「この30問ではこうだった」という意味で、実際の使い方での正確さを保証するものではありません。**

## 測り方

採点ツールは [DowasureEval/main.swift](../DowasureCore/Sources/DowasureEval/main.swift) です。アプリと同じ `Retriever` と `Answerer` をそのまま使います。

1. 問題ごとに、「質問した日」の正午に聞いたことにする（日本時間）。その日より後の記録は無いものとして渡す。
2. `Retriever.candidates` で候補の日（最大7日）を選ぶ。ここまでは通信しない。
3. `--live` の時だけ、`Answerer.answer` で本物の Claude に聞き、アプリと同じ `Answerer.verify` を通した答えを採点する。

| 指標 | 意味 | 正しいとする条件 |
|---|---|---|
| 正答 | 答えがある質問に正しく答えた | 「見つかった」と答え、根拠の日付が正解の日付と1つ以上重なり、答えの文に正解の言葉が入っている |
| 作らない | 記録に無い質問に「見当たりません」と答えた | 「見つからない」と答えた |
| ヒントが付く | 正答のうち、AI のヒントが1つ以上ある | アプリが代わりに作る日付のヒントは数えない |
| ヒントの漏れ（自動） | 正答のうち、ヒントに正解の言葉が入っている | 少ないほど良い。**採点データ側の正解の言葉** で調べるので、AI が返した `answer_keywords` に頼るアプリ内の点検とは別の目になる |
| 検索の拾い上げ | 正解の日が、AI に送る候補に入った | 通信なしで測れる |
| 1位で当たり | 正解の日が、候補の1番目だった | 同上 |
| 待ち時間 | 1問の質問から答えまでの秒数 | `--live` の時だけ |

ほかに、正答のヒントを全部画面に出します。**人が読んで、言い換えの漏れを確かめるため** です（自動の点検は言葉の一致しか見ないため）。

### 動かし方

```bash
cd DowasureCore
swift run DowasureEval                    # 検索だけ。通信しない
swift run DowasureEval --live             # 本物の AI。鍵を secrets/anthropic_api_key（または環境変数 ANTHROPIC_API_KEY）に置いた時だけ
swift run DowasureEval --live --effort low  # AI が考える量を変えて比べる
```

結果は `DowasureCore/eval-results/latest.json` に書かれます（コミットしません）。

### 11/07 のヒントの直し（人の目で見つけたもの）

自動の点検は 11/07 の採点で毎回漏れ0でしたが、ヒントを全部読むと、次の漏れが見つかりました。どれも指示文を直して消しました。

| 見つけた漏れ | 直し |
|---|---|
| 「『や』で始まる、グラウンドで走り回るスポーツ」（＝野球）、「雪のような色」（＝白） | 連想で答えが1つに決まる書き方を禁止。考える量 `low` はやめた |

まだ残っていること（次に直す候補、開発記録 11/07 17:45〜）：1けたの数のヒントが弱め。ある問題では2つ目のヒントから日付を計算できてしまう。日にちを聞いているのに最後のヒントが月の話。別の質問の答えが、他の質問のヒントに出てくることがある。

## 限界（正直に）

- **合わせ込みの恐れ。** 採点データは制作側が作ったもので、30問と少なめです。漢字1文字の一致やヒントの決まりは、このデータを見ながら直したので、実際より良い点が出ている可能性があります。
- **データの形が今のアプリと違う。** 採点データの記録は、文章で書いた話と、あらかじめ書いた抜き出し結果でできています。今のアプリの記録は「[16:05] にんじんを買う」のような短い行と、Haiku が作った抜き出しです。抜き出し（`Recorder`）の出来は、この採点では測っていません。
- **長い期間を測っていない。** 採点データは約1か月半分です。「去年」「3か月前」「夏ごろ」など1〜2年使う前提の時期の言葉は、単体テスト（`timeWordsForLongUse` など）で日付の範囲だけを確かめています。
- **1回ずつしか流していない。** 同じ条件で何回か流した時のばらつきは測っていません。
- **ヒントの漏れの自動点検は言葉の一致だけ。** 言い換えの漏れは人の目で読んで見つけています。漏れの判定そのものを別の目で見る係（`.claude/agents/hint-leak-judge.md`）の判定は、上の表の「漏れ（自動）」の列に括弧で載せています（[係の点検.md](係の点検.md)）。
- **待ち時間は Mac から測ったもの。** iPhone では、これに声を作る時間（約3秒、11/03 計測）などが加わります。
- **次にやること。** 藤川の実際の記録で確かめ直します（その記録はリポジトリに入れません）。
